# 告别超长命令行：lounger Web Runner 让用例「随点随跑」

> 一个内置于 lounger 测试框架的测试运行器：一条命令启动，浏览器里浏览、筛选、执行、看日志、翻历史。
> 本文基于 **Lounger Web Runner v2**（lounger 1.6.0）编写。

---

## 一、先说痛点：你一定这样跑过用例

在 IDE 里点单个用例执行，看着很爽——**前提是用例足够「独立」**。

一旦用例引用了全局配置、共享 fixture、环境变量，IDE 里那条「▶」就点不动了：收集阶段就失败，或者跑起来报错，但你在命令行里跑同一个用例却是好的。

于是只能退回到最原始的方式：**在项目根目录敲命令，把长长的 nodeid 敲进去**。

```
pytest test_dir/vip_tire_case/test_vip_tire_add_step2_service.py::test_add_vip_tier_service_vip_running
```

这种名字还不是一个两个，而是这样成对的：

```
test_dir/vip_tire_case/test_vip_tire_add_step2_service.py::test_add_vip_tier_service_vip_running
test_dir/vip_tire_case/test_vip_tire_upd_step2_service.py::test_upd_vip_tier_service_vip_running
```

`add` / `upd` 只差三个字母。终端智能补全有时也会补错，结果你跑了一个**不存在**的用例，白等一次收集才发现。

跑完还不算完——还得在终端里往上翻，从一堆输出里找到失败的那一段，再复制出来贴给同事。

**这些琐碎但高频的摩擦，就是我动手做一个测试运行器的原因。**

## 二、当时我列了 5 个愿望，现在全部兑现

做之前我给自己列了一份清单：

| # | 愿望 | 现在 |
|---|---|---|
| 1 | 解析整个项目所有用例，细化到每一条 | ✅ |
| 2 | 单个执行、多个执行、全部执行 | ✅ |
| 3 | 实时查看执行日志，不用回终端 | ✅ |
| 4 | **YAML 用例也能单条运行** | ✅ 🌟 |
| 5 | 加上用例统计 | ✅ |

第 4 条当初我自己标了个「🌟」——因为绝大多数测试运行器只认 pytest 函数，YAML 写的用例只能整文件跑，单条执行是个盲区。**lounger Web Runner 把 YAML 用例也解析成了树上的独立节点，可以单独运行。**

而 v2 又在愿望清单之外加了：**运行历史、标签筛选、收藏**。

## 三、它能做什么

### 3.1 一条命令启动

```bash
cd your-project            # 在业务项目根目录
lounger runner --port 5001

🚀 lounger web runner → http://127.0.0.1:5001
   Project: /path/to/your-project
   Press Ctrl+C to stop.
```

打开浏览器，整个项目的用例树就在左侧。

> 可选参数：`--host`（默认 127.0.0.1）、`--port`（默认 5000）、`--project`（默认当前目录）。

### 3.2 用例发现：pytest 与 YAML 一视同仁

- **pytest 用例**：零配置，自动收集；
- **YAML 用例**：在 `config/config.yaml` 的 `test_project` 里勾选目录即可加载，且**每条 YAML 用例都是树上一个可单独运行的节点**；
- 顶部实时统计：`📊 共 N 用例 | pytest: N | YAML: N`；
- 搜索框支持模糊匹配，几百条用例里定位一条只需要敲几个字；
- 用例有更新？点【🔄 刷新用例列表】重新收集。

### 3.3 想怎么跑，就怎么跑

| 场景 | 操作 |
|---|---|
| 跑一条 | 鼠标悬停在用例上，点 ▶ |
| 跑一个文件 | 悬停在文件上，点 ▶▶ |
| 跑一批 | 勾选复选框 → 【▶ 执行选中】（配合【全选】/【取消】） |
| 跑全部 | 【▶▶ 执行全部】 |

外加 **4 档日志粒度**，随时切换：**静默 / 标准 / 详细 / 完整**（对应 pytest 的 `-q` / 默认 / `-v -s` / `-vv -s`）。

调一个用例时用「详细」，跑全量回归时切「静默」——不用改配置，页面上点一下就行。

### 3.4 日志实时推到浏览器

- 基于 **SSE 流式推送**，日志边跑边出，不用等整轮结束；
- 按结果自动着色：**PASSED 绿 / FAILED·ERROR 红 / 跳过·警告 黄**，扫一眼就知道结果；
- 【📋 复制日志】一键复制全文——贴给同事、写进缺陷单，比截图体面；
- 【🧹 清空日志】随时清屏，重新跑一轮干干净净。

### 3.5 v2 新增：运行历史

每次执行都会被**自动归档**：时间、用例数量、完整日志。

- 切到【📜 历史记录】页签，就能看到历次运行；
- 点开任意一条可以回看**完整日志**，也能【📋 复制】；
- 不需要的记录可以删除；
- 内存里的运行记录是有界的，久的自动落盘，长时间挂在后台也不会越跑越胖。

「昨天那次失败到底报了什么？」——不用再翻终端历史了。

### 3.6 v2 新增：标签筛选与收藏

- **⭐ 收藏**：把冒烟用例、核心链路收藏起来，页面上点一下「⭐ 收藏」就只看这些；
- **标签筛选**：按用例标签快速圈定范围；
- 跑过的用例在树上带颜色标记，**哪条刚跑过、哪条还没碰过，一眼可见**。

### 3.7 细节都是给「天天用」准备的

- 侧栏可拖拽调宽，宽度和树的展开状态**本地记忆**，下次打开还是你熟悉的布局；
- 用例名、文件路径 hover 显示完整信息，长名字不再被截断成谜；
- 右上角状态灯：运行中 / 全部通过 ✅ / 执行失败 ❌ 一目了然；
- 浏览器页签自带 favicon（内联 SVG，零外部请求）；
- 运行状态可见：状态灯 + 「运行中 (N 用例)」提示 + 运行计数，且运行期间执行按钮自动禁用，避免误点重复触发。

## 四、为什么它好用：几个技术选择

| 维度 | 说明 |
|---|---|
| **零额外依赖** | 后端是 Python 标准库的 `ThreadingHTTPServer` + SSE，前端是内置的单页 HTML。**不引入 Node、不需要数据库、没有前端构建流程**——`pip install lounger` 就有 |
| **与命令行同源** | 用例收集与执行都走 pytest（子进程），页面上跑的就是命令行跑的那一套。不存在「运行器一套、CI 一套」的行为漂移 |
| **YAML 用例是一等公民** | YAML 用例被解析为独立节点，可单条运行、可单独失败定位 |
| **可编程** | 提供 HTTP API，CI / 平台 / IDE 插件都能复用：`/api/tree`（用例树）、`/api/run`（发起运行）、`/api/stream/<run_id>`（实时日志）、`/api/history`（运行历史） |
| **历史落盘** | 运行记录归档为 JSON，进程重启不丢 |
| **不侵入框架** | 运行器只消费框架能力（收集 / 执行），不改变被测项目的写法 |

## 五、快速开始

```bash
# 1. 安装
pip install -U lounger

# 2. 在业务项目根目录启动（YAML 用例需先在 config/config.yaml 勾选目录）
cd your-project
lounger runner --port 5001

# 3. 打开浏览器
open http://127.0.0.1:5001
```

三步之后，你就可以：**点用例 → 看日志 → 复制失败信息 → 改代码 → 再点一次**，全程不离开浏览器。

## 六、它适合谁

- 用例引用了全局配置 / 共享 fixture，**IDE 里点不动**的同学；
- **不想记 nodeid** 的人（尤其是那些只差几个字母的孪生用例名）；
- 需要**把失败日志快速分享**出去的测试同学；
- 用 **YAML 写接口用例**、却苦于只能整文件跑的人；
- 想把「执行测试」这件事**接进平台 / CI / 内部工具**的团队（HTTP API 已就绪）。

## 七、写在最后

做这个运行器的出发点很小：**少敲一次命令、少一次敲错、少一次翻终端**。

但用久了会发现它对协作方式的改变更大——用例可以被「看见」了：有多少条、属于谁、跑过没有、上次为什么失败。测试资产从「终端里的命令」变成了「浏览器里的清单」。

试试看：

```bash
pip install -U lounger && lounger runner
```
